# SPA (Single Page Application)

- 서버로부터 새로운 페이지를 load 받지 않고 필요한 부분(데이터-json)만 동적으로 변경하는 웹 어플리케이션  
  → 처음 페이지를 불러올 때 HTML, CSS, JS 파일을 전부 미리 받아와서 미리 클라이언트 측에서 준비를 해놓는 상태를 말한다

> [!info]
> 초기 SPA는 AJAX 통신을 활용하여 필요한 데이터를 동적으로 바인딩하는 방식을 채용했으나, 서비스 규모가 커짐에 따라 수동적인 DOM 조작 비용이 증가
> 이를 해결하기 위해 상태 변화에 따라 UI를 업데이트 해주는 React, Vue과 같은 라이브러리와 프레임워크 등장

## SPA의 장단점

### 장점

- 초기 렌더링 시 어플리케이션 가동에 필요한 정적 파일을 받아오므로 이후 새로고침을 할 필요가 없음

- 끊기는 모습이 없고 부드러운 UX 제공

- 사용자는 JS 번들이 로드된 후 화면을 봄과 동시에 인터렉션이 가능하므로 TTV와 TTI 사이의 간극이 거의 없음

- 이후의 동적에서 추가적인 정보가 필요한 경우, 필요한 리소스만 요청하기에 서버와 부담이 상대적으로 적음

- 기존에는 서버에서 렌더링 된 페이지를(SSR) 받았다면 SPA의 경우 최초 요청 이후 내부에서 렌더링을 하기에 서버와의 부담을 분산

> [!info]
> TTV: Time to View<br/>
> TTI: Ttime to Interact

### 단점

- 초기 어플리케이션 가동에 필요한 대부분의 리소스를 받아야 하기에 페이지가 곧바로 로딩되지 못함 (로딩이 느림)

- TTV가 상대적으로 늦음, 렌더링 전까지 사용자는 빈 화면만을 바라보게 됨

- 이를 해결하기 위해 많은 양의 JS 코드를 번들링하여 분할 제공하는 Code Splitting 기법이 있으나 근본적인 해결은 못됨

- 초기 HTML이 비어있는 경우가 많기 때문에 SEO가 어려움

# MPA (Multiple Page Application)

- SPA 이전에 쓰인 전통적인 페이지 로드 방식

- 여러개의 페이지로 이루어진 어플리케이션이며 새로운 페이지를 요청할 때마다 서버에서 렌더링된 정적 리소스를 전달

- 다른 페이지로 이동하거나, 새로고침이 진행될 경우 서버에서 페이지를 다시 렌더링 진행

## MPA의 장단점

### 장점

- 서버에서 사전에 렌더링 된 정적 리소스를 받음으로서 빠르게 어플리케이션에 화면을 띄울 수 있음

- TTV가 SPA에 비해 월등히 빠름, 사용자는 사전에 렌더링 된 페이지를 보여주기만 하면 되기 때문

- 서버에서 사전에 만들어진 HTML을 전달 받기 때문에 SEO에 유리

### 단점

- 화면을 빠르게 보여줄 수 있으나, 동적인 인터렉션을 담당하는 JS파일을 적용하기까지의 텀이 존재

- TTI가 TTV보다 상대적으로 늦음,

- 페이지를 이동할 때마다 결국 서버에서 렌더링 된 파일을 받아야 하기에 매 요청마다 깜빡이는 현상이 발생

- 서버에서 매 요청 시에 보내야 할 데이터의 사이즈가 커지면 서버 트래픽이 증가
